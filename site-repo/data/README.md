# Mount Saint Mary's Cemetery: canonical data

Built 2026-09-04 from the board's List of Names sheet (Sections A–C), the
arbitrated paper-map transcriptions (Sections A–H and the newer lettered east
field), the cross-check workbook, and the Plots Sold ledger. Everything in this
folder is regenerated by `../build_data.py`; `validate.py` checks it.

## The key: `lot_id`

Every record hangs off `lot_id`, formatted `<SECTION>-<LOT>` with no zero
padding: `A-1`, `F-134`, `K-21`. Sections A–H are the eight original blocks
inside the loop drive and use integer lot numbers. In the newer east field the
**column letter I–W is the section** and the **row number 1–80 is the lot**, so
`K-21` is column K, row 21. `lot_id` is unique, stable, and is the join key for
every other file here, including a future surveyed geometry.

## Tables

| File | One row per | Notes |
|---|---|---|
| `lots.csv` | lot, **every** lot in every section, 2,610 in all | `status` is one of open / sold / occupied / reserved / unusable / unknown. `unusable` marks X blocks, crossed-out cells, trees and the statue/reserved area. `burial_count` is the number of `people.csv` rows on that lot. `purchaser`, `year_sold`, `price`, `paid` come from the Plots Sold ledger and are board-only. |
| `people.csv` | burial or memorial, 910 rows | `person_id` is sequential (`P00001`…). `source` says where the name came from: `sheet`, `paper`, `paper+sheet` (both sources, merged), `headstone`, `findagrave`, `board`. `confidence` is high / medium / low, carried from the transcription; a sheet name the paper disagreed with is kept as written and demoted to `medium`, with the paper's reading in `note`. |
| `sections.csv` | section, 23 rows | Column layout as `startlot:width_ft;…` west to east, numbering direction, block extents, and where the geometry came from. |
| `monuments.csv` | survey monument | Empty apart from two rows marked `EXAMPLE` that show the format. Northing/easting are Missouri State Plane West, NAD83, US survey feet (EPSG:2817, verify before relying on it). Delete the EXAMPLE rows once real monuments are set. |
| `changes.csv` | change event | Append-only log (`timestamp, who, kind, lot_id, details`); a Google Form appends to it. Never edit or delete rows. |
| `lots.geojson` | lot polygon | WGS84 lon/lat, `properties: {lot_id, section, lot, geometry_source}`. |
| `sections.geojson` | section polygon | Same convention, one polygon per section block / east-field column. |
| `georef.json` | n/a | The anchor, the scale, and every layout assumption, so the site can re-derive the geometry and a survey can replace it. |
| `import_report.md` | n/a | Counts per table and per section, the A–C merge tallies, and open questions. |

## Privacy rule

`purchaser`, `price`, `paid`, `year_sold`, board `notes`, `updated_by`,
`updated_on`, and the whole of `changes.csv` are **board-only**. The public
build carries only `lot_id`, `section`, `lot`, `status` collapsed to
open / taken / unusable, and the people fields (names, years,
`findagrave_url`). `people.csv` deliberately contains no purchaser or price
columns at all, and `validate.py` fails if any appear.

## Accuracy caveat

The geometry here is **approximate**. It is derived from the column widths
written on the paper number grids plus a single anchor, the northwest inside
corner of the loop drive, placed from the cemetery's published coordinates
(39.13670, −93.30580, Find a Grave cemetery 31354, read 2026-09-04) assuming the
map is north-up and that the published point is the centre of the mapped area.
Absolute position is good to roughly **10–20 ft**; the spacing *between* lots
follows the paper and is better than that. Every polygon says so in
`properties.geometry_source = "paper-approximate"`, and every lot in `lots.csv`
says `geometry_source = paper`. Do not use these shapes to locate a grave in the
field, mark a burial, or settle a boundary question.

## Replacing the geometry with a survey

Nothing but the two GeoJSON files depends on the anchor, so a survey drops in
cleanly:

1. Produce polygons for the surveyed lots with a `lot_id` property using exactly
   the ids in `lots.csv` (`A-1`, `K-21`, …).
2. Replace the matching features in `lots.geojson` (or the whole file) and set
   `properties.geometry_source` to `"survey"` on the surveyed ones.
3. Set `geometry_source` to `survey` in `lots.csv` for those same `lot_id`s, and
   update `sections.csv` / `sections.geojson` the same way if the block corners
   were surveyed too.
4. Record the monuments in `monuments.csv` (removing the EXAMPLE rows) and note
   the change in `changes.csv`.
5. Re-run `python3 data/validate.py`. It enforces that every polygon's `lot_id`
   exists in `lots.csv` and that every lot still has exactly one polygon, so a
   partial or mis-keyed survey file fails loudly instead of quietly dropping
   lots.

The records tables never change during a survey. The join is `lot_id`, and only
`lot_id`.
